分层可导航小世界图

从原理到实现：HNSW 完整理解指南

2026-06-04
阅读时长: 10 分钟
向量检索
HNSW NSW 最近邻问题 最近邻搜索 六度人脉 ANN 向量检索

1. 背景与动机

当数据（图片、音频、文本）被 Embedding 模型向量化后，如何从海量向量中快速找到最近邻是一个核心问题（最近邻问题），这个过程称为最近邻搜索（Nearest Neighbor Search）。

精确最近邻（KNN）需要 O(N*d) 的暴力比较，数据量稍大就无法接受。近似最近邻搜索（ANN） 通过牺牲一点点精度换取数量级的加速，HNSW 是目前 ANN 领域的 SOTA 方案之一。

参考论文：Efficient and robust approximate nearest neighbor search using Hierarchical Navigable Small World graphs (Malkov & Yashunin, 2016)

2. 理论基础：六度分隔与可导航小世界

核心理论是六度人脉：世界上任意两人平均只需 6 个中间人就能建立联系。

2.1 可导航小世界公式

$$ \text{局部密友} + \text{少量远程捷径} = \text{任意两点之间距离极短} $$

2.2 为什么需要远程捷径

纯局部连接形成的是网格/聚类——跨区域必须逐跳穿过中间节点，路径长度与节点数成正比（O(√N)）。加入少量随机长边后，任意两点跳数降至 O(log N)，这就是小世界图的核心性质。

3. 单层 NSW（Navigable Small World）

3.1 结构

  • 稠密本地连接：每个向量只和离自己最近的 M 个向量建立连接（精确近邻边）
  • 少量随机长边：插入过程中，新节点被随机连接到的早期节点会成为"枢纽"，自动形成长边

3.2 搜索算法（贪心 KNN Search）

function SEARCH_NSW(query, entry, K):
    // 从 entry 出发，每一步只走到离 query 最近的邻居
    cur = entry
    while True:
        nearest = None
        minDist = INF
        for neighbor in neighbors(cur):
            d = distance(neighbor, query)
            if d < minDist:
                minDist = d
                nearest = neighbor
        if minDist >= distance(cur, query):
            break  // 无法再改进 → 局部最优
        cur = nearest
    return cur  // 近似最近邻

贪心搜索返回的是局部最优而非全局最优，但因为小世界图的拓扑性质，这个局部最优通常离全局最优很近。

3.3 优点与局限

优点：结构简单、高维友好、任意两点跳数少（5~6 跳）。

局限：

  • 数据量百万级以上，跳数增长到 7~9 跳
  • 没有全局入口策略——从任意点出发，第一次跳的目的地不可控
  • 搜索路由可能先"绕远路"再收缩

4. 多层 HNSW（Hierarchical NSW）

4.1 设计思想

仿照社会分层：顶层是"跨领域大佬"（节点少、长边多），底层是"普通人"（全量节点、本地连接）。搜索时从顶层快速定位区域，逐层下沉精细搜索。

图层结构：

  • Layer L（顶层）：节点数最少，全是长边。类比社会名流
  • Layer 1：节点指数级增多，长短边混合
  • Layer 0（底层）：全量节点 + 稠密近邻边，负责最终精准搜索

4.2 核心优势

从顶层一路贪心到底层，搜索路径从单层的 56 跳压缩到 **24 跳**。关键改进在于找到最好的起点——顶层节点天然就是优质入口。

5. 核心算法详解（以实现为导向）

5.1 层级分配 (Level Generation)

每个节点被分配一个随机层级 l，服从指数衰减分布：

1
2
3

function GET_RANDOM_LEVEL(mL):
    // mL = 1 / ln(M)，控制衰减快慢
    return floor(-ln(uniform(0,1)) * mL)

性质：

  • P(level ≥ k) ∝ exp(-k/mL)，每上升一层节点数约除以 M
  • 顶层期望节点数 = totalNodes × (1 - 1/M)^{topLayer}
  • 例如 M=16, N=100万，顶层约 100万 × (1-1/16)^{3} ≈ 550 节点

function SEARCH_LAYER(query, entry, ef, layer):
    visited = set()
    candidates = MinHeap()   // 按距离升序，待探索
    results   = MaxHeap()    // 按距离降序，当前 top-ef 候选

    visited.add(entry)
    candidates.push(entry, dist(entry, query))
    results.push(entry, dist(entry, query))

    while candidates is not empty:
        c = candidates.pop()          // 离 query 最近的候选
        furthest = results.peek()     // 当前候选中最远的
        if dist(c, query) > dist(furthest, query):
            break                     // 无法再改进（关键剪枝）

        for neighbor in adj_list[c][layer]:
            if neighbor not in visited:
                visited.add(neighbor)
                f_dist = dist(results.peek(), query)
                d = dist(neighbor, query)
                if d < f_dist or |results| < ef:
                    candidates.push(neighbor, d)
                    results.push(neighbor, d)
                    if |results| > ef:
                        results.pop()  // 移除最远的

    return results  // 返回 ef 个候选节点


function SEARCH(query, K, ef):
    cur = entryPoint
    // 从最高层逐层下降到第 1 层（每层只走 1 个近邻）
    for l in topLayer .. 1:
        cur = SEARCH_LAYER(query, cur, ef=1, l).pop()
    // 底层用完整的 ef 搜索
    return SEARCH_LAYER(query, cur, ef, 0).topK(K)

为什么高层用 ef=1？ 高层只为找到下一层入口点，不需要过多候选——选最好的一个就够了，减少无用计算。

function INSERT(node, M, Mmax, Mmax0, efConstruction, mL):
    level = GET_RANDOM_LEVEL(mL)
    cur = entryPoint

    // 1. 从顶层搜索到 level+1 层，确定入口
    for l in topLayer .. level + 1:
        cur = SEARCH_LAYER(node, cur, ef=1, l).pop()

    // 2. 从 min(level, topLayer) 向下插入到 0 层
    for l in min(level, topLayer) .. 0:
        candidates = SEARCH_LAYER(node, cur, efConstruction, l)
        M_layer = (l == 0) ? Mmax0 : M
        neighbors = SELECT_NEIGHBORS(node, candidates, M_layer)

        // 双向连接
        for neighbor in neighbors:
            add_edge(node, neighbor, l)
            add_edge(neighbor, node, l)
            // 如果某节点连接数超限，裁剪其邻居
            if degree(neighbor, l) > limit(neighbor, l):
                shrink_connections(neighbor, l)

        // 3. 更新下一层的入口为当前层找到的最佳点
        cur = closest(candidates)

    // 4. 如果新节点的 level 比当前顶层高，更新全局入口
    if level > topLayer:
        entryPoint = node
        topLayer = level

5.4 SELECT-NEIGHBORS 邻居选择策略

这是 HNSW 的核心创新之一。两种策略：

Simple 策略（默认回退）：

1
2
3

SELECT_NEIGHBORS_SIMPLE(candidates, M):
    // 直接取距离最近的 M 个候选
    return sort_by_distance(candidates)[:M]

问题：选出来的邻居全挤在一起，缺乏"可导航性"。

SELECT_NEIGHBORS_HEURISTIC(candidates, M, layer, query):
    // candidates 按距离 query 排序
    result = []
    queue  = sort_by_distance(candidates)  // 升序

    // 第一轮：贪心选，只选"非冗余"的
    for c in queue:
        if is_closer_to_existing(c, result, query):
            continue    // c 离某个已选邻居比离 query 更近 → 冗余
        result.append(c)
        if |result| == M:
            return result

    // 第二轮：如果不够 M 个，从最近者补足
    for c in queue:
        if c not in result:
            result.append(c)
            if |result| == M:
                break
    return result

其中 is_closer_to_existing 检查 dist(c, query) > dist(c, any_result)，如果成立说明 c 被已有邻居"覆盖"了，不需要重复连接。

启发式选择的效果：生成的邻居在空间中分布更发散，远程捷径更丰富，搜索路径更短。

论文推荐：底层用 Mmax0 + heuristic，上层用 M + simple。这是因为底层需要高精度（heuristic 发散好），上层只需要快速路由（simple 足够且更快）。

5.5 连接剪枝 (Shrink Connections)

当一个节点的度数超过该层限制（M_max 或 M_max0）时，需要裁剪多余连接——同样用 heuristic 策略保留最"有价值"的邻居。

function SHRINK_CONNECTIONS(node, layer):
    candidates = all_neighbors(node, layer)
    new_neighbors = SELECT_NEIGHBORS_HEURISTIC(candidates, limit(layer), layer, node)
    set_neighbors(node, new_neighbors, layer)

6. 参数体系深度解析

6.1 核心参数总表

参数 含义 典型范围 默认值（FAISS） 对召回的影响 对延迟的影响
M 每层（非底层）最大连接数 12~48 32 M ↑ → 图更密，召回↑ M ↑ → 遍历任务↑，延迟↑
M_max0 底层最大连接数 2M~4M 64 ↑ → 底层精度↑ ↑ → 底层搜索慢
ef_construction 建图时搜索宽度 100~400 200 ↑ → 图质量↑（边际递减） ↑ → 建图慢（O(N log N) → O(N ef log)）
ef 搜索时候选队列大小 10~500 — ↑ → 召回↑（调优最直接） ↑ → 线性增加延迟
mL 层级衰减率 1/ln(M) ~ 1/log2(M) 1/ln(M) 大 → 上层节点多，路径长 太大 → 检索变慢；太小 → 顶层过快到底

6.2 M 与 M_max0 的关系

  • M_max0 通常设为 2*M 或更大，因为底层承担最终精度
  • 如果 M_max0 = M，底层节点的连接数容易被暴力剪掉太多，导致召回下降
  • 实现中 limit(l) 在 l==0 时返回 M_max0，否则返回 M

6.3 ef_construction 的选择

  • ef_construction ∈ [M, 上限 ~2000]
  • ef ∈ [1, 上限]
  • 关系：ef_construction ≥ ef（否则建图搜索窄于检索，不合理）
  • 典型搭配：ef_construction = 200（建图），ef 从 20 ~ 500（运行时动态调）

召回-ef 曲线有边际递减，建议画一次曲线找出拐点。

6.4 mL 的推导

$$ m_L = \frac{1}{\ln(M)} $$

这个值保证每向上一层，期望节点数除以 M。推导：

在底层（level=0）有全部 N 个节点。一个节点出现在 level≥k 的概率是 $1/M^k$，所以 level≥k 的期望节点数是 $N / M^k$。当这个值小于 1 时，顶层建立：

$$ \frac{N}{M^{L}} < 1 \Rightarrow L > \log_M N = \frac{\ln N}{\ln M} $$

所以顶层高度 ≈ $\ln N / \ln M$，M=32, N=100万 时顶层 ≈ 4 层。

8. 工程实现注意事项

8.1 删除操作（HNSW 的软肋）

HNSW 原生不支持删除。删除一个节点意味着必须重建所有与被删节点相连的边——这在多层结构中极其复杂。

常见方案：

  1. 惰性标记（Tombstone）：标记删除，搜索时跳过。简单，但被删节点仍占用内存，删除多了图质量下降
  2. 标记 + 周期性重建：累积到阈值（如 20%）后重建整个索引
  3. 原地替换：将删除节点的邻居重新连接（实现复杂，几乎不用）

实践中大部分生产系统（Milvus、FAISS）采用方案 1+2

8.2 更新操作

HNSW 不支持更新，通常实现为删除 + 重新插入。频繁更新的场景建议考虑其他索引（如 IVF 或磁盘方案）。

8.3 内存占用分析

每一层存储：

  • 节点 ID（int）：4B
  • 邻居列表（边）：每邻接 4B（指针）+ 距离值如果用预计算可额外存储

单节点内存 ≈ (M_max0 + M * avgLayers) * 4B + 固定开销

Estimate for N=100万, M=32：

  • 底层连接数 ≈ N × M_max0 = 100万 × 64 = 6400万条边
  • 上层连接数 ≈ N × (1 + 1/M + 1/M² + …) × M ≈ 100万 × 1.03 × 32 ≈ 3300万条边
  • 总边数 ≈ 1亿条边 ≈ 400MB~800MB（看指针/距离存储方式）

实际中 HNSW 内存占用约为原始数据的 2~5 倍（取决于 M 和 M_max0）。M=32 时，100万 128维 float 数据约占用 1~2GB。

8.4 并发安全

  • 搜索（读取）：天然支持无锁并发——搜索只读，不修改图
  • 插入（写入）：需要加锁。常见做法：
    • 全局读写锁（简单但写入时阻塞搜索）
    • 逐层锁 + CAS（复杂，高性能）
    • 批量插入后重建（离线场景）

8.5 内存随数据增长的分析

HNSW 是纯内存索引，数据规模超过可用内存时无法工作。大规模（亿级以上）的选择：

  1. DiskANN：HNSW 思想的磁盘版，用 SSD 分页存储图，只加载热数据到内存
  2. 分布式 HNSW：按 ID 范围分片，每台机器一个独立图，用 Router 合并结果（Milvus 方案）
  3. 混合：Product Quantization (PQ)：压缩向量后用 HNSW，适合显存不足的 GPU 场景

为什么 HNSW 仍然是"最好"的？

  • 召回-延迟 Pareto 前沿最先进——同等召回率下延迟最低，同等延迟下召回最高
  • 一个索引搞定，不需要训练（IVF 需要训练聚类）——部署简单
  • FAISS、Milvus、Qdrant、Weaviate、Chroma、Elasticsearch 都在用

什么时候不用 HNSW？

  • 数据规模超大且内存不足 → DiskANN / 分片
  • 需要频繁增删改 → IVF / DiskANN
  • 需要确定性精确结果 → KD-Tree / Brute Force
  • 部署在 GPU 上 → GPU-IVF（HNSW 不擅长 GPU 并行化）
